# 西瓜离线原型：M0–M1

本轮实现[产品方案](xigua-implementation-plan.zh_CN.md)中的本地交互与持久化基础，硬件验收待完成。
它与原额度固件独立，不包含额度查询凭据。

本页记录 M0–M1 基线。当前源码已加入 [M2 联网增量](xigua-m2.zh_CN.md)，
其中的联网与 AI 配置说明替代下文仅离线阶段的相关描述。

## 范围与操作

- 开机进入重新设计的中文卡片界面，上下键切卡，OK 进入。
- 长按 UP 快速记奶，默认 150 ml 或最近一次奶量；上下每次调整 10 ml，OK 保存。初始输入范围 10–400 ml。
- 奶量页长按 OK 在新增与修改最近一次之间切换；接入语音 PTT 时会调整这个原型手势。
- 睡眠和趴玩分别开始/结束；尿布、洗澡通过对应页面记录；本地计时器提供屏幕提醒。
- 长按 DOWN 返回。保存后首页提供 5 秒撤销入口，绑定最近一次已提交的操作与版本。
- 离线查看历史和累计统计。绝对时间未知时明确显示，不把累计值冒充准确今日合计。
- 30 秒自动变暗，60 秒熄屏；首次完整按键手势只唤醒，不保存或开始操作。
- 电量来自 BSP；读取失败显示未知。

本轮未启用 Wi-Fi 连接、配网、校时、语音及声音播放，这些属于后续阶段，不以模拟结果代替。
音频阶段之前，计时器只作视觉提醒。

## 数据约定与限制

原型最多保存 **128 条事件**，不是后续 4,000 条目标。不会自动淘汰旧记录，满容量后拒绝新增。
导出、历史选择删除和更大日志存储尚待实现；不要把原型作为重要记录的唯一副本。

核心使用明确版本、小端编码、长度及 CRC 校验的快照。存储适配层采用两个交替 NVS 槽、代数和外层校验。
控制器是唯一写入者：先修改候选状态，提交快照成功后才发布结果。提交失败或结果不确定后停止继续写入，等待重启；
数据损坏时可回退至较早有效快照，但进入只读，不擦除任何槽。无效数据不会触发自动格式化。

最近 16 个成功命令 ID 用于重试去重；开始接收新命令前先递增并持久化启动编号。
这是有界本地重放保护，不是无限历史的同步机制。

同次启动的时长按单调时钟计算。重启后无法还原的区间标为未知，不拿不同启动的 uptime 相减。
旧启动中的不确定计时器需明确取消/重新开始。纯逻辑核心保留可信时间回填接口，供后续接入；当前原型不会伪造 UTC 或时区。

## 固件布局及数据影响

原型保留已有 NVS、PHY 位置与应用起点，缩小 factory，在 Flash 尾部预留产品专用 256 KiB NVS：

| 分区 | Offset | Size |
| --- | --- | --- |
| nvs | `0x9000` | `0x6000` |
| phy_init | `0xF000` | `0x1000` |
| factory | `0x10000` | `0x7B0000` |
| xigua_data | `0x7C0000` | `0x40000` |

此表仅供 M0–M1，暂时代替完整产品方案中的分区草案，不修改上游通用基线约定，也不提供 OTA。
首次安装会替换额度应用和分区表。从 `0x0` 写入合并镜像可能重置默认 NVS/PHY，不保证保留数据。
后续若改数据布局，刷机前需要迁移/导出；不得用整片擦除作为自动修复方式。

## 验证与设备交接

在激活的 ESP-IDF 5.5.3 环境运行 `tools/validate.sh`。针对性测试覆盖命令/时间/快照、双槽故障、
按键释放注册及短按/长按/唤醒手势；完整门禁还包含仓库原有用例。
产物位于 `build/`，只有核验过的合并固件可写到 `0x0`。

Windows 下对含中文路径启用 Python UTF-8 模式。本地主机编译器/actionlint 包装器放在忽略的
`build/host-bin` 与 `build/host-tools`，不是产品依赖。宿主缺少符号链接权限时应单独报告环境失败，不削弱用例。

获准刷写后检查：

1. 无网络冷启动能显示真实中文、电量并响应每个实体按键。
2. 记奶、修改和撤销均有反馈，记录数与预期一致。
3. 睡眠/趴玩开始结束正常；中途重启显示不确定时长。
4. 尿布、洗澡、历史、满容量、计时到点与取消符合预期。
5. 熄屏唤醒不会触发额外动作。
6. 用可丢弃记录做写入中断与提交恢复测试，再信任持久化。
7. 所有标签、错误页无缺字/截断，反复切页正常。

构建、主机测试与现场观察必须分开报告。构建或刷写成功不能证明显示、断电恢复和续航。
