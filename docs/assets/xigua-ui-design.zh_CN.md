# 西瓜助手界面与三键交互设计 v1.0

这份文档定义西瓜助手在 FoloToy AI Passport 上的第一版界面逻辑。它是后续
`main/xigua/` 实现的交互基线；本文件描述的功能只有在对应的本地存储、音频、
联网或语音模块完成并通过验证后，才能在设备上标记为可用。

## 1. 设计目标

设备只有 240×320 竖屏、三个共用 ADC 分压按键、8 MB Flash、ESP32-C3 和
无 PSRAM。界面因此只解决一个问题：家长在抱着孩子、注意力很短的情况下，
能用一只手完成一次记录，并且始终知道这次按键会做什么。

- 本地记录不依赖 Wi-Fi、云服务或语音；网络只是设置和语音的增强能力。
- 页面每次只呈现一个主要动作，避免三键在同一页面承担互相冲突的含义。
- 记录写入完成前显示“保存中”，只有持久化成功才显示“已记录”。
- 任何新增记录在首页保留 5 秒撤销入口；撤销只绑定这一次操作的事件 ID。
- 所有页面顶部固定显示时间可信度、网络状态和电量。电量读不到时显示 `--`，
  不猜测充电状态。

## 2. 页面地图

开机直接进入“概览”，不再进入硬件测试菜单。页面之间用单层返回关系组织，
不使用隐藏的侧滑或触摸手势；密码键盘明确提示双击 UP/DOWN 换行。

| 页面 | 作用 | 进入方式 | 离开方式 |
| --- | --- | --- | --- |
| 概览 | AI 助手和讲故事优先，之后是手动记录、今天、睡眠、声音、Wi-Fi 和设置 | 开机；任意顶层页面长按 DOWN | OK 进入当前焦点；UP/DOWN 切换卡片 |
| 喂养 | 记录时间、奶量、食材/备注；固定选项先离线可用 | 概览选中“喂养”后 OK | OK 进入编辑；长按 DOWN 返回 |
| 大小便 | 记录尿布类型和发生时间 | 概览选中“大小便”后 OK | UP/DOWN 选尿/便；OK 保存 |
| 睡眠 | 后台睡眠记录及持续时间 | 概览“开始睡眠／结束睡眠”卡片 | OK 切换状态，不进入计时页 |
| AI 助手 | 处理问答文字和记录 JSON | 概览首项 OK | 按住 OK 说话；长按 DOWN 返回 |
| 讲故事 | 独立语音故事页；收到回复后自动播放 | 概览第二项 OK | 按住 OK 说话；长按 DOWN 返回 |
| 儿歌/白噪音 | 浏览云端曲目，暂停、继续、停止或刷新 | 首页第二项“儿歌”按 OK | UP/DOWN 选择；OK 执行选中曲目或控制项 |
| 今天 | 按类别显示今日统计和最近记录 | 概览选中“今天”后 OK | 长按 DOWN 返回；UP/DOWN 翻页 |
| 设置 | 显示、声音、Wi-Fi、时间、AI、设备信息和重启 | 概览选中“设置”后 OK | 长按 DOWN 返回；破坏性操作另有确认页 |
| Wi-Fi/时间/AI | 显示状态和测试结果；自动连接已知网络，扫描／选择 SSID，再输入密码 | 设置对应项 | UP/DOWN 选择；OK 进入；长按 OK 完成文字；长按 DOWN 返回 |
| 结果/错误条 | 显示保存中、成功、失败、可重试和撤销 | 任何写入或测试动作后 | 超时回到原页；OK 撤销或重试 |

页面不是同时创建的。每次只保留当前页面、当前状态快照和少量文本，退出页
前先停止访问该页对象的任务、定时器和回调，再删除 LVGL 对象。

## 3. 概览页布局

240×320 屏幕从上到下固定为四块：

1. **页头**：常驻时间、网络、电量状态栏，下方为当前页面标题。
2. **内容区（204×190 px）**：两行奶量／睡眠／尿便摘要，以及最多三个高 38 px、
   间距 6 px 的菜单卡片。
3. **反馈行**：没有操作反馈时显示菜单页码。
4. **固定两行按键提示**：上下选择、确认打开、长按上键快速喂奶。

概览焦点顺序固定为“AI 助手 → 讲故事 → 手动记录 → 今天 → 睡眠 → 声音 → Wi-Fi 配网 → 设置”。
三页分别显示 3、3、2 项，首尾循环。上下键在 PRESS 时立即移动，驱动随后报告 DOUBLE
也不会让快速连续按键停止移动。卡片与 AI 准备／操作菜单共用深蓝底色、青色选中填充、
深色选中文字和白色外框；仅在概览页创建。短暂撤销窗口优先于打开普通菜单项，
睡眠卡片始终执行当前显示的开始／结束动作。
AI 助手和讲故事是两个独立的上层入口：语音识别结果交给大模型，由模型通过 JSON 调用记录功能，
或返回文字；讲故事页收到正文后自动播放。手动记录保留为离线兜底，不与 AI 助手争夺首页焦点。
音频播放、网络状态变化和
电量变化不能改变当前焦点，避免 OK 的含义在用户按下前悄悄改变。

## 4. 三个按键的统一规则

按键硬件是 GPIO0 上的三档 ADC 分压：UP 约 0 mV、DOWN 约 300 mV、OK 约
595 mV。应用不读取 GPIO 电平，也不在按键回调里访问 LVGL；底层回调只入队，
由应用任务顺序处理。

| 手势 | 普通浏览页 | 编辑/选择页 | 确认或错误页 |
| --- | --- | --- | --- |
| UP 单击 | 上一张卡/上一项 | 数值减 10；上一选项 | 上一选项；不执行危险动作 |
| DOWN 单击 | 下一张卡/下一项 | 数值加 10；下一选项 | 下一选项；不执行危险动作 |
| OK 单击 | 打开焦点或执行主动作 | 保存/开始/播放 | 确认当前高亮项；结果条中执行撤销或重试 |
| UP 长按 | 快速打开“奶瓶”，沿用上次奶量 | 连续减 10，松开后停 | 被忽略 |
| DOWN 长按 | 返回上一级；顶层回到概览 | 取消编辑，不保存 | 取消并返回；顶层不触发破坏性操作 |
| OK 长按 | 在问答/故事页按住说话；普通记录页显示语音入口 | 录音页松开后提交；不自动保存文字 | 禁用语音，防止确认页误录音 |

长按动作不能在按下瞬间提交数据。UP 长按只打开奶量编辑页，OK 单击才保存；
DOWN 长按直接取消当前编辑。这样任何一次误触都不会写入一条完整记录。

当前 BSP 只有 LONG，没有可靠的 RELEASE 事件。启用按住说话前必须给 BSP 增加释放事件，按下
时预热音频，释放时提交录音，并用 3 秒看门狗处理丢失释放事件。不能把 LONG
事件冒充录音结束。

## 5. 各页面的具体交互

### 5.1 快速记录与奶量编辑

首页直接显示八个主要入口，避免再套“更多”层级。喂养编辑页把奶量放在中央
大字号位置，底部始终写明 `▲ -10 ml  ▼ +10 ml  ● 保存`。保存时把精确时间写入与语音记录共用的本地事件环。
确认文字显示记录的日期和时间，“今天”页显示最近喂养的时间、奶量和食材。
时间自动取可信时钟；
食材先从固定选项选择，备注和任意食材由语音交给大模型补充。范围暂定 10–400 ml；
超出范围提示“请人工确认”，不能静默截断。

点击保存后进入短暂的 `保存中` 状态，按键被忽略但 UI 仍可刷新电量。写入成功
显示“已记录 150 ml”，并给出 5 秒 `● 撤销`；写入失败显示“保存失败 / ● 重试 /
▼ 取消”，原页数据不提前增加。

### 5.2 大小便页

大小便页只有两个选项“尿”和“便”，按 OK 立即写入本地事件和时间，不启动计时。
未来语音可以补充颜色、性状和备注；设备离线时至少保留发生时间和基本类型。

### 5.3 睡眠页

睡眠作为后台会话运行。概览卡片在“开始睡眠”和“结束睡眠”之间切换，按确认直接执行，
不进入专用计时页；离开概览、记录喝奶、使用语音或另一个计时器均不会打断睡眠。
结束时保存一条包含精确开始时间、精确结束时间和计算时长的记录。进行中的卡片显示开始日期和时间，
“今天”页可用上下键翻页查看当前会话和最近完成的睡眠。同一次开机内用单调时钟计算，跨重启
用可信时间戳计算；时间不可信时显示“时长待校准”。洗澡和趴玩仍为单次记录。

现有持久化结束时间字段用 `-1` 表示睡眠进行中，原有状态 blob 保持不变。
精确起止时间放在以事件环索引对应的独立版本化 NVS blob 中，回退时仍可读取原记录。
加载时迁移旧版活动页的睡眠状态；旧固件不识别这个时间 blob 和后台会话标记。
本次改动以前的历史记录通常显示开始时间未知，只有最近一条旧会话能够安全补齐时才会补齐。

### 5.4 AI 助手、结构化记录和故事

AI 助手页面处理问答和记录，独立的讲故事页处理故事提示词；两者共用 PTT、ASR、模型和 TTS 基础链路。
按住 OK 才开始录音，松开才提交；短按 OK 不发送空请求。

已实现的 AI 界面分为准备、录音、处理中、回复查看、回复操作和失败状态。
准备页有三个高亮卡片：长按确认说话、查看上次回复、返回。短按确认不发送固定提示词，也不开始录音；
仅在准备页的录音卡片长按确认才开始录音，松开结束。处理中忽略确认键，保留上一次成功回复。
回复在独立裁切区域使用完整 20 px 字库显示；上下键在按下时按五行、每行 38 px 换页，
焦点移动、单击和双击均不会发起新请求。确认打开操作菜单，默认选中继续查看；
再问一次先返回准备页，仍需明确长按。
故事正文先显示，再自动朗读。按确认打开四项操作：“暂停朗读／继续朗读”（空闲时为“开始朗读”）、
“从头重读”“继续查看”和“再讲一个”。暂停保留下一块 PCM 的位置，继续使用同一段音频，
不重新生成故事或调用 TTS；从头重读重置播放游标。播放与暂停时均可上下翻页；
正文页长按下键取消当前播放并返回首页，操作菜单长按下键退回正文页。“再讲一个”取消旧播放并返回准备页。
朗读失败保留正文供重试。四项卡片均位于 190 px 正文区域内。
故事提示词要求 500–700 个汉字并完整收尾。SSE 解码器使用 1 KiB PCM 缓冲增量处理大段 base64 音频。
31 抽头低通滤波器将服务端 24 kHz PCM 转成 12 kHz，语音时长与音调保持不变；
IMA ADPCM 将每个独立块压缩至 PCM 大小的约四分之一。
使用现有 2 MiB `voice_tmp` 临时分区保存音频块，替代约 21 KiB 的 RAM 队列，可容纳约 5.7 分钟语音；
超出容量会明确失败，不覆盖未读音频。播放前擦除，写入完整块成功后才发布可读数据。
Flash 读写放在临界区外，缓存写入期间 I2S 中断保持在 IRAM。
独立 PCM 任务先缓冲三秒音频（12 kHz 下 72,000 字节解码后 PCM）再播放；不足三秒的完整短语音直接播放。
暂停先排空已提交的 DMA 采样、休眠 codec 并保留下一块位置；网络接收继续写入 Flash，
避免 RAM 队列装满后阻塞服务端语音流。继续时唤醒 codec 并从游标读取后续音频。
整段接收完后，即使喇叭仍暂停，也会关闭 HTTP 连接。缓冲耗尽会重新缓冲。
日志记录暂停／继续游标、缓冲耗尽次数、供数间隔与栈余量；主动暂停不计入供数间隔。
完整缓存通过 SHA-256 绑定当前回复，可不连接 Wi-Fi 直接重播。新录音会复用该临时分区并使语音缓存失效；
应用退出或重启会丢失内存中的缓存有效标记和播放位置。录音与下载未缓存回复仍需要 Wi-Fi／TTS。
NVS 中的记录和设置与临时音频缓存相互独立。
TLS 接收上限设为 16 KiB，因为 MiMo 会发送完整大小的记录；降为 8 KiB 会导致朗读期间
mbedTLS 报错 `-0x7100` 并中断。TLS 在每次连接时预留 16 KiB 接收缓冲和 4 KiB 发送缓冲，在 HTTP client 清理时释放。
禁用逐记录动态申请：实际机器重播时曾间歇性出现 `-0x7F00`，播放途中无法获得完整记录所需的连续内存。
收到 HTTPS 响应头后再启动 PCM 任务。
回复缓冲为 4096 字节，放在任务栈之外。助手回复输出预算为 1024 token，故事为 2048 token，聊天 I/O 超时为 45 秒。
本地截断保留完整 UTF-8 字符，服务器返回 `finish_reason: length` 也会标明部分回复。
后台服务自检不会覆盖回复。预置提示词要求完整的纯文字段落，优先控制在 500 个汉字以内，
即使用户要求也不输出 Markdown、空行、emoji 或装饰符号。模型仍可能违反指令，因此 worker
在显示前压缩空行、去掉常见 Markdown 标记和 emoji；整理在命令校验之后执行，不处理尚未解析的 JSON。

服务端提示词要求模型严格区分两类返回：

```json
{
  "actions": [
    {"action": "record_feeding", "time": "15:20", "amount_ml": 150, "ingredient": "FORMULA"}
  ]
}
```

提示词区分已发生的事实与咨询、否定、计划和假设。“刚喝了 150 毫升奶”提交记录，
“应该喝多少奶”返回正文；缺少必要信息时用纯文字追问。

| 语音动作 | 必要字段／效果 |
| --- | --- |
| `record_feeding` | `amount_ml` 为 10–400 的整数；只有明确食材时才附 `ingredient`（`FORMULA`／`BREAST_MILK`） |
| `record_diaper` | `kind` 为 `pee`／`poop` |
| `record_sleep` | 已结束的睡眠，`duration_min` 为 0–65535 的整数分钟 |
| `record_bath` | 一条洗澡记录 |
| `record_tummy` | 一条趴玩记录 |
| `start_sleep` | 开始后台睡眠；已在睡眠时拒绝重复开始 |
| `end_sleep` | 结束当前睡眠并计算时长；未开始时拒绝结束 |

只有用户给出时间时才附当天 `HH:MM` 的 `time`，省略则取设备时间。worker 只接受完整 JSON 对象，
其中必须恰好有一个白名单动作；格式损坏、被截断、多个动作、未知动作或无效字段均不提交。
NVS 保存成功后才将 JSON 替换为设备生成的确认文字并提供撤销；保存失败恢复原状态并报错。
普通正文不会更改记录。设置、Wi-Fi、计时器和声音播放未开放为语音命令。
旧的 `reply_text`／`tts_text` 响应 API 保留兼容。讲故事页使用独立的 `mimo-v2.5-tts` 流式接口，
将每个 `delta.audio.data` Base64 分片解码为 24 kHz、16 bit、单声道 PCM，经滤波转为 12 kHz 后通过 BSP 音频路径播放；
普通 AI 回复暂时只在屏幕显示。儿歌和白噪音在共享 AI 工作任务中校验规范 WAV 后播放 PCM。

### 5.5 音频库页

“音频库”是首页第二项，在第一屏三张卡片中可见。云端目录最多缓存 16 首儿歌、益智故事、早教古典音乐或白噪音曲目，浏览时保留分类标签并显示为“儿歌”“益智故事”“早教古典”“白噪音”。
UP/DOWN 选择曲名或“暂停／继续”“停止”“刷新”控制项，OK 执行所选项。
播放前校验规范的 12 kHz、16 bit、单声道 WAV。暂停保存已输出 PCM 字节位置，
关闭 HTTP、休眠音频芯片，并让共享 AI 工作任务返回队列；继续时校验 HTTP Range 后从保存位置续播。
进入 AI 助手或讲故事页会取消儿歌，录音等其他音频请求也可接管资源。
选择另一首曲目会取消并替换当前播放或暂停的会话，取消后不会自动重播。
暂停位置仅保存在 RAM 中，重启或流传输失败后需要重新发起播放。

### 5.6 今天页

今天页使用分页而不是滚动列表：第一页是奶量、睡眠和尿布摘要，后面依次是当前／最近睡眠和最近喂养记录。
喂养详情包含时间、奶量和食材。UP/DOWN 翻页，OK 打开选中记录的只读详情；详情页的
撤销需要明确二次确认。没有记录时仍提供“返回”和“去快速记录”，不能让空列表
堵住导航。

### 5.7 设置、网络和时间页

儿歌的目录和控制见 5.5，DOWN 长按返回。页面退出前停止或移交可能访问 UI 的任务，
不能让已经删除的页面继续接收回调。音频工作任务不保存或访问页面对象。

Wi-Fi 开机扫描后检查全部扫描结果，优先尝试当前可见的三个内置网络，再尝试
已保存网络。连接失败时对关联超时等原因重试三次；自动模式用尽候选后，间隔
15 秒重新扫描。手动搜索接管无线流程。蓝牙配网和手动 SSID 输入均已移除。

密码软键盘为六列、最多五行字符；大写和小写各自在一页显示全部 26 个字母，
数字／符号分两页。类型切换和退格／换页／完成固定显示在底部两行。当前键用
青色填充、深色文字和白色外框高亮。每次按下 UP/DOWN 都立即移动，双击从这次
手势的起始键向上／下移动一行；连续快速按三次或更多次仍能移动。OK 选择，
长按 UP 退格，长按 OK 完成，长按 DOWN 取消。密码显示为掩码。键盘控件只在
编辑时创建，退出时释放，为 TLS 保留堆空间。Wi-Fi 和 MiMo 预设使用所有者授权
的 Git 管理配置。

Wi-Fi 页区分“已连接”“无 IP”“
互联网待确认”和“服务鉴权失败”，不要把一次探测失败统称为断网。时间页显示
时间来源和可信度，并提供手动校准入口；没有可信时间时记录仍可保存，但标记为
待校准。

每页底部都显示当前页提示，例如 `UP -10  DOWN +10  OK save`。不增加首次使用
教程；用户随时能从屏幕底部看到当前操作。

## 6. 状态与反馈

所有动作使用同一组状态：`待操作 → 已受理 → 进行中 → 已完成`，失败时进入
`失败/可重试`，用户取消进入 `已取消`。状态变化在同一位置更新，避免弹窗覆盖
主要内容。网络或音频忙时仍允许返回、切换页面和查看今天页；慢操作在 worker
执行，按钮回调和 LVGL 任务只做有界的入队或快照更新。

结果条的文案必须包含“做了什么”和“下一步按什么”：

| 状态 | 示例 |
| --- | --- |
| 受理 | `正在保存 150 ml…` |
| 成功 | `已记录 150 ml · 5 秒内 ● 撤销` |
| 失败 | `保存失败 · ● 重试 · ▼ 返回` |
| 网络 | `网络待确认 · 可继续离线记录` |
| 时间 | `时间待校准 · 记录仍会保存` |
| 存储满 | `存储已满 · 请先导出记录` |

这些短句优先使用内置 Source Han Sans SC 16 CJK 覆盖的固定字集；新增动态中文
必须重新做逐字 glyph 检查。数字、单位和时间可以使用 Montserrat，但混排时要
检查基线和行高。

## 7. 硬件与资源边界

- 不使用全屏背景图、视频或全屏双缓冲。页面由少量 LVGL 容器和文本组成，遵守
  240×320 单 240×20 RGB565 绘制缓冲和 24 KB LVGL 池的现有预算。
- 顶部状态栏和底部按键栏高度固定，中间内容只在自己的区域换页，避免遮挡电量
  或圆角屏幕遮罩。
- 页面空闲约 20 秒后降低或关闭背光；熄屏后的第一次完整按键只唤醒，不能同时
  执行动作，防止抱持设备时误记一条记录。
- 网络、TLS、音频录音和 Flash 写入都在 worker 中运行。录音将 16 kHz 单声道
  PCM 流式写入录音分区，最长 60 秒。2 KiB 采样缓冲只在录音时申请，成功或读写失败
  均释放，避免占用共用的 6 KiB AI 任务栈。录音日志记录栈高水位，但这些诊断信息
  本身不能证明实机重启的原因。
- 页面退出顺序固定为“停止 producer → 等待退出确认 → 持 LVGL 锁删除定时器和
  对象 → 清空对象指针”。任何回调都不得保存页面对象地址。
- 默认分区仍保持 NVS、PHY 和单 factory；事件日志或音频资源若要新增分区，必须
  先有容量、断电恢复和刷写数据影响证据，不能为 UI 方便直接改模板分区。

## 8. 本地事件与服务端衔接

每次喂养、尿、便、睡眠开始、睡眠结束、洗澡和趴玩都先生成一个本地事件，事件
至少包含类型、设备单调时间、可信墙上时间（若已校时）和参数。离线时只写本地，
联网后由同步任务按事件 ID 上传；上传成功才标记已同步，失败继续保留并退避重试。
服务端摘要不能覆盖原始事件，语音识别得到的食材、备注和故事提示词也要保存
原文与模型结果的来源。

AI 返回的 JSON 是设备和服务端之间的稳定协议。设备只接受白名单动作、数值范围和时间字段，未知动作
进入错误提示，不执行任何副作用。当前固件先在 NVS 保存有界事件队列，后续同步服务端时沿用事件 ID，
而不是把模型的一段自然语言重新解析一遍。

## 9. 实现顺序与验收

第一阶段先实现离线可用的喂养、大小便、睡眠、今天和设置，并把事件写入本地有界
日志；用主机状态机验证导航和幂等。第二阶段接入真实时间、Wi-Fi/AI 配置、问答和
独立讲故事页的 PTT/ASR/TTS。第三阶段接入儿歌/白噪音服务端流式播放和离线事件同步。洗澡、
趴玩等非核心事件沿用同一事件接口，不复制计时页面。

每个阶段都要分别记录：

- 主机状态机测试：UP/DOWN 循环、OK 保存、长按取消、重复 command 不重复写入、
  空列表和存储满状态。
- 固件构建：镜像大小、最大堆和最大连续堆块，以及实际启用的中文字体配置。
- 真机检查：每个页面、每个按键手势、熄屏首键、中文混排、音频/网络失败和页面
  反复进退。

在没有真机观察前，中文字形、背光唤醒、按键长按边界、实际存储写入耗时和电池
续航都保持为未验证项。

## 10. 记录上下文、交接、纠错和提醒（2026-10-01）

应用在设置之后新增两个首页入口：照护交接、提醒，沿用现有应用页面设计。
交接页先显示最近的本地喂养、睡眠和尿便，再显示缓存的云端摘要与家长留言。
UP/DOWN 翻页，OK 请求朗读，长按 DOWN 返回首页。云端数据保留同步时间；
没有记录不会被解释成没有发生。网页工作台新增交接页，可持久保存最多160字的
家长留言。设备定期更新，需要后端也升级到本版。

普通助手请求带上有界本地记录、按当地日期计算的奶量／尿便／睡眠统计、
进行中的睡眠、当前当地日期时间和提醒。缓存的服务器近七天摘要包含快照版本
和时区。本地与云端统计不得相加。时间未校准、32条记录环已满均明确标识。
普通回复的操作菜单增加第四项“朗读回复”，朗读仍为可选操作。故事生成和
自动服务自检不携带这些记录上下文。

补记接受当地 `YYYY-MM-DD HH:MM`，或 `HH:MM` 搭配0至365的 `days_ago`。
无效日期和未来的记录时间会被拒绝。睡眠补记接受 `start_time`、`end_time`，
设备计算跨日期时长。`edit_last_feeding` 可修改最近保存的一条喂养的奶量、
时间或奶种。设备显示修改前后内容，默认取消，必须选中保存再按 OK。预览
五分钟后过期；目标记录已变化或被覆盖时拒绝保存。成功修改沿用事件序号，
同步不新增重复记录，并保留原有五秒撤销窗口。暂不支持修改其他类型的记录。

`create_reminder` 接受简短 `title`，以及1至10080的 `delay_min` 或准确当地
时间 `at`，二者选一。`cancel_reminder` 需要屏幕显示的整数 `id`。最多八条
单次提醒存入独立的 `care_v1` NVS 键。到时弹出设备页面，音频空闲时排入

不打断音频、录音和回复处理。提醒不会执行标题里的动作，也不生成医疗或喂养

## 11. 常驻状态栏与手机配置方案（2026-10-01）

所有应用页面现在都有独立的第一行，显示本地 `HH:MM`、网络状态和电量。
LVGL 每秒刷新一次，停留首页或阅读回复时也会更新。时钟未达到现有可信时间戳
阈值时显示 `--:--`；设置时区后立即使用对应本地时间。页面标题放到下一行，
不缩小内容阅读区或密码键盘区。数字字段使用 Montserrat 14，网络文字使用已
检查覆盖范围的 16 像素中文子集。电量未知或无效时显示 `--%`。

状态栏优先使用当前 Wi-Fi 状态，不被旧的服务自检结果覆盖。`已连接` 表示已
获得 IP、尚未确认公网 HTTPS 检查；`自检中` 表示现有自检正在运行；`已联网`
表示最近一次公网 HTTPS 探测成功，即使后续模型调用失败也保留这一网络结论。
公网探测失败显示 `联网失败`。这些是现有定期探测的结果，不是持续外网或育儿
后台可用性测量。LVGL 定时器不执行网络请求。SSID、IP 和模型详情仍在现有
页面查看。

NFC 与手机配置流程是下一阶段方案，本次状态栏修改没有实现这些功能。板载
NTAG213 是无 MCU 接口的被动标签。手机可写入含管理入口 URL 的 NDEF URI
记录；刷固件不会修改标签内容，MCU 也无法感知手机碰触。
[NTAG213 数据手册](https://www.nxp.com/docs/en/data-sheet/NTAG213_215_216.pdf)
规定用户空间为 144 字节，足够保存短入口网址。标签只保存入口地址，管理登录
和 BLE 配置授权单独处理。iPhone 后台读标签会先显示通知，点通知后打开链接，
见 [Apple 说明](https://developer.apple.com/videos/play/tech-talks/702/)。
Android 的打开行为也随版本变化，见 [Android NFC 文档](https://developer.android.com/develop/connectivity/nfc/nfc)。

手机管理页可集中配置多组 Wi-Fi 名称、密码和优先级，替换 API Key，并分别
选择对话、ASR、TTS 模型。拟定配置事务为：设备进入配置模式、手机连接、
读取非敏感设置、修改、校验、完整配置持久化到 NVS、工作任务应用、回传配置
版本和连接结果。页面遮蔽密码与 Key，BLE 读取和日志不回显已保存的敏感值。
传输中断应保留上一份有效配置。保留用户已授权的编译预置作为回退配置，由
明确的 NVS 配置覆盖；日常改配置不需要重新编译固件。

[Chrome Web Bluetooth](https://developer.chrome.com/docs/capabilities/bluetooth)
支持 Android Chrome 的 BLE GATT 读写，需要安全上下文以及用户点击选择设备。
当前 HTTP 管理地址需要先提供可信的 HTTPS 入口。NFC 打开页面不能省掉
“连接设备”的点击。Safari/iOS 目前不支持该 API，见
[MDN 兼容性数据](https://developer.mozilla.org/en-US/docs/Web/API/Web_Bluetooth_API)。
iPhone 路径需要原生 BLE 客户端，或手机浏览器通过设备临时 Wi-Fi 热点完成
配置。手机平台与 HTTPS 地址仍待确定。设备端需要新增应用 GATT 服务、有界
配置报文和本机授权窗口，完成或超时后关闭 BLE。选择并发策略前应测量固件
体积与 Wi-Fi、BLE、TLS、音频同时运行的堆内存，这块板没有 PSRAM。
