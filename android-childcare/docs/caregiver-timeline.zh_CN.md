# 照护者时间线

Android 0.6.6-cloud 和管理端的记录页提供竖向每日时间线。时间列和连续轴线连接记录卡片，例如爸爸 08:30 喂奶 150 毫升、妈妈 09:10 换尿布。记录按真实发生时间从早到晚排列，相同时间按稳定 ID 排序。未登记发生时间的记录单独标注，排列在已知时间之后，不计入当天合计；与所选日期重叠的睡眠仍会显示。

## 登记与录入

安卓“家庭”页维护宝宝资料和持久化照护者名单，通过“我是孩子的 ___”一个称谓输入框登记，支持修改与停用。填写爸爸、爷爷、奶奶等称谓即可，不再要求姓名或电话。新记录把称谓保存为已有的照护者姓名快照，因此云端时间线使用相同称谓，无须改服务器结构。已有成员优先使用关系，关系缺失时沿用旧称呼。新记录默认使用当前选择的照护者。记录页的“记喂奶”“记换尿布”直接打开确认表单；统一照护入口也会把语音或文字中的照护动作转到该表单。补记可选择其他照护者，也可明确选择未登记。仅说“上厕所”时不会擅自填写尿布类型。

每条记录保存当时的姓名快照。修改姓名或停用成员不会改写历史记录；编辑旧记录时默认保留原快照，重新选择才改变归属。旋转屏幕后恢复编辑表单与照护者选择。奶量可输入小数；只修改照护者时，空奶量、未知尿布类型和导入记录的未知发生时间仍保持未知。

管理端宝宝页提供对应的喂奶、尿布录入和照护者姓名编辑，并从已有记录的姓名快照提供建议。成人记录表格及编辑器继续保留；姓名和备注均按纯文本显示。安卓名单保存在本机：同步的是记录归属，本次没有向服务端新增电话、名单管理、账户认证、邀请或共享照护者通讯录。

## 同步与兼容

个人 API 接受可选的 `data.caregiver`，例如 `{ "id": "opaque-local-id", "name": "爸爸" }`；管理端直接填写姓名时 ID 可为 null。姓名不能为空，最多 40 个字符；ID 最多 128 个字符。明确传 null 会清除归属；旧客户端编辑时省略该字段，服务端保留现有快照。原有操作回执身份及语义摘要不变。

服务端声明 `childcare_caregiver: true` 后，安卓才会上传姓名归属。不支持此能力的服务会让具名记录留在待同步队列，并显示原因。v3 已冻结且不含归属的操作原样重放，确认后再发送新的归属更新。冲突处理中选择保留本地记录，也会保留本地明确选择的照护者，包括清空姓名。服务端和档案身份隔离机制继续生效。

`GET /records?order=timeline` 可选用发生时间升序。成对的 `start`/`end` 日期和 IANA `timezone` 选择日期窗口，默认行为兼容旧客户端。管理页分页固定 `at_revision`，切换日期会重置分页；安卓每页 100 条。本扩展不需要 SQLite 或服务端迁移。

只修改照护者时，原始发生时间、区间、独立提供的睡眠时长、来源、媒体、未知字段，以及可空的喂奶和尿布细节均保留。缺少区间时间的历史睡眠保持历史状态，不会变成正在计时的睡眠。排序使用真实时刻而非时间字符串；本地时间遇到夏令时跳跃或重复区间时，需要另选明确时间。

## 验证与运行

产物哈希、准确测试数量和实机验收见[交付证据](delivery.zh_CN.md)。新增协议与表单回归测试先复现冲突恢复丢失照护者、未知或自定义细节被替换、擅自填写时间、未改动睡眠数据被重算，再验证修复。测试使用临时数据库和本地测试服务；实机仅进行同签名升级和只读页面操作，不向家庭数据库写入合成记录。

APK 沿用 v3 的签名，SQLite 仍为版本 3。使用 `adb install -r` 升级，不清除应用数据；保留私有签名密钥，以便后续升级。原有语音发送与 ASR 生命周期、多套服务 URL/key 配置和模型发现仍可使用。

管理端修改已在本地完成并测试，生产部署是另一项操作。生产服务声明新能力之前，具名记录会留在手机等待同步。大规模生产历史记录、服务端排序容量和网页累积分页尚未负载测试；限制与分配归属见[安卓资源预算](resource-budget.zh_CN.md)和服务端资源预算（协调项目源码：`../../backend/contracts/resource-budget.zh_CN.md`）。
