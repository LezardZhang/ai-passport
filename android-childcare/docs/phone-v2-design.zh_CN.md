# 手机照护流程与配套机制

## 用户意图
主人认为手机菜单过细，应用不能只停留在“能运行”。语音和大模型能力共用照护入口，由语音或文字意图选择后续动作；人物需要登记、管理和资料更新。沿用此前自主实施授权，不增加重复设计审批。

## 产品设计
三个入口：照护、记录、家庭。照护只有一个可编辑的语音/文字输入框，可表达记录、问答、故事、播放、提醒和查询。写入记录进入现有结构化编辑器确认；含糊、否定、多动作和补记输入不能静默保存。关于喂养或睡眠的提问仍是提问。统一界面背后继续保留请求身份、类型和取消归属。

家庭包含现有一个宝宝档案（云端固定身份 baby）、生日等资料以及本机照护者名册。照护者可登记、修改、切换、停用和恢复；当前照护者须先切换才能停用。历史记录保留原照护者快照。数据库升级保留原有数据。本机人物登记不等于云端账号认证；现有固定令牌接口没有跨手机身份管理，已向用户核对范围。

以 MiMo 识别配合原生录音，避免依赖目前不可用的 Google 组件。AudioRecord 把16kHz单声道PCM写入限额临时WAV；结束录音转为可编辑文字，取消或退到后台释放录音并使回调失效；专用传输流式编码Base64。集成检查发现已有 Token Plan 密钥可用于其编程端点，但普通应用 API 拒绝该密钥。交付 APK 不带密钥，家庭入口提供普通 API 配置流程。系统识别保留为显式备用。文字AI优先使用已配置的后端，否则使用已配置的MiMo；失败可见，重试由用户触发。普通应用凭据下的实际麦克风语音仍待验证。

版本维护显示实际安装版本和可选HTTPS发布频道。发布清单包含包名、递增版本号、最低系统、APK地址、SHA256和说明。下载及导入限额，检查包名、版本和签名身份，再打开Android安装确认。未配置频道不能声称能在线升级。清理中断暂存。保持包名、签名和SQLite数据完成覆盖升级。

## 范围与验证
只修改android-childcare。后端及固件只读；不启用Google组件，不清空真机，不发布或部署。版本号2 / 0.2.0-local沿用原签名。主机测试覆盖意图、资料校验、更新清单；独立仪器测试覆盖v2→v3迁移、照护者状态及历史归属、请求恢复；模拟器验证三入口、字号、旋转和生命周期。验证后覆盖安装到已连接手机，并单独报告云账号与生产发布能力的缺口。
