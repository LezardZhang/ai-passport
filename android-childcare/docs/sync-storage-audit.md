# Code13 sync and storage audit

The October 3, 2026 local audit found no automatic whole-archive upload in Xigua Childcare 0.6.6-cloud. No application change, rebuild or publication is needed. The APK SHA256 matches the published code13 receipt, and the nine source files used for this audit match the code13 build manifest. [Machine-readable evidence](../reports/sync-storage-audit-v13.json).

| Flow | Actual behavior and source |
| --- | --- |
| Automatic care sync | Startup and record changes schedule a network job; a periodic job also runs at Android's permitted interval, with a 15-minute requested period. `SyncService` calls `Api.sync()`, never archive export. [Scheduler](../app/src/main/java/cn/xigua/childcare/SyncService.java), [startup](../app/src/main/java/cn/xigua/childcare/CareApp.java). |
| Record uploads | Only pending outbox operations are posted to `/sync/push`, one operation per JSON request, at most 100 per run. Each operation contains the affected record representation; it is not a field-only patch or a complete database snapshot. [API](../app/src/main/java/cn/xigua/childcare/Api.java), [outbox selection](../app/src/main/java/cn/xigua/childcare/Store.java). |
| Receipt and retry | Applied receipts remove the acknowledged outbox row. A failed/lost receipt can cause the same frozen operation ID and payload to be retried. This is record-level retry, not repeated ZIP backup. |
| Downloads and other requests | Pull uses a revision cursor, baby profile and pages of up to 100 changes. Capability, profile and optional family-profile requests are JSON reads. Optional backend AI job requests are separate JSON operations, not backups. |
| ZIP export | The only production caller of `BackupArchive.write` is the successful result of the explicit export document picker, request 51. It writes to the user's selected document URI. A chosen cloud document provider may save that explicit export remotely, but the app does not schedule or upload ZIP archives itself. Android system backup is disabled by `allowBackup=false`. [Export UI](../app/src/main/java/cn/xigua/childcare/MainActivity.java), [archive](../app/src/main/java/cn/xigua/childcare/BackupArchive.java), [manifest](../app/src/main/AndroidManifest.xml). |
| APK publication | The local publisher posts the signed APK to the independent `/android-updates/publish` endpoint only when invoked explicitly. A normal build and the Android app cannot publish releases. [Publisher](../tools/publish-update.py), [release command](../tools/release-update.sh). |
| Update checks | Automatic checks fetch the manifest at most once per six hours; APK download requires the download button. The primary and legacy update routes both proxy the independent service on port 8916. The legacy Cloud Backup URL prefix is a compatibility alias, not general backup storage. [Update client](../app/src/main/java/cn/xigua/childcare/Updates.java), proxy (coordinated source: `../../backend/deploy/android-updates.nginx.conf`), isolated release volume (coordinated source: `../../backend/deploy/android-updates.compose.yml`). |

The built-in family data endpoint remains `/cloud-backup/app/v1`, separate from release storage. The code13 asset has no family token, so a fresh installation without a previously stored token stops before data requests. This audit does not claim successful real household synchronization, current phone configuration, live request traffic, or server storage retention. No server, Chrome or 1Panel operation was performed.

Build: NOT RUN for this audit; existing code13 build passed. Host tests: NOT RUN for this audit; existing code13 host validation passed 134 assertions. Device tests: NOT RUN for this audit; ADB has no connected physical device, and code13 installation remains pending. Unverified: physical code13 acceptance, family credential provisioning and live family sync.
